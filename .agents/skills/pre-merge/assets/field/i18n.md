# Internationalization

## After rebase

- **Conflicts.** Two keys added to the same locale file by the two sides
  plainly survive: keep both. The same key given different text on each
  side is two intents: stop and ask.
- **Checks.** When the default branch and this branch both changed the
  source-locale files (the ones AGENTS.md names), check after the rebase:
  - no key is defined twice in one locale file;
  - every key the branch's code uses still exists in the source locale (the
    default branch may have renamed or removed it). Some builds fail on a
    missing key only in production, or fall back silently, so look rather
    than trusting a passing gate.

  A duplicate or a missing key is fixed on the branch and committed before
  phase 1a step 5 runs the gates.

## Rebuild

A new localization key that a spec or LLD names goes in the documentation
bucket with the doc that introduced it, though it lives in a localization
file outside `docs/`. Keys the docs do not name go with the implementation.
